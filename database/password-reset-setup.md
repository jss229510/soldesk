# 비밀번호 재설정 설정

## 팀원용 간단 실행 (Windows)

처음에는 자기 Oracle 프로젝트 계정에서 `database/05_password_reset.sql`을 한 번 실행한다. 이미 만든 경우 다시 실행하지 않는다. 기존 USERS 테이블은 삭제하지 않는다.

VS Code에서 backend 폴더의 PowerShell 터미널을 열고 아래 한 줄을 실행한다.

```powershell
.\run-local.ps1 -Mail
```

처음 묻는 값은 다음과 같다.

1. `Oracle JDBC URL`: 자기 DB 주소. 기존에 `localhost:1521:xe`로 연결했다면 Enter를 누른다. XEPDB1 등 다른 주소를 쓰면 그 주소를 입력한다.
2. `Oracle username`: 자기 DB 계정. soldesk면 Enter를 누른다.
3. 비밀번호 창: 자기 Oracle 비밀번호를 입력한다.
4. `Sending Naver email address`: 메일을 보낼 네이버 이메일 주소를 입력한다.
5. 비밀번호 창: 네이버 로그인 비밀번호가 아닌 **앱 비밀번호**를 입력한다.

보내는 네이버 계정에서 2단계 인증과 앱 비밀번호 발급, 메일의 IMAP/SMTP 사용함 설정이 필요하다. 받는 이메일은 사이트에 가입돼 있어야 한다. 메일 업체에 계정을 만드는 작업은 각자 직접 한다.

`Started ComcheckApplication`이 나오면 서버 실행 성공이다. 설정값은 현재 터미널에만 남고 파일에는 저장하지 않는다. 같은 터미널에서 다시 실행하면 이미 입력한 설정을 사용한다. 터미널을 새로 열면 다시 입력해야 한다.

입력값을 다시 설정할 때는 `.\run-local.ps1 -Mail -Settings`를 사용한다. 실제 메일 발송을 확인하지 않을 때는 `.\run-local.ps1`로 실행해도 된다. `-Mail`을 빼는 것은 새 메일 설정을 묻지 않는다는 뜻이며, 같은 터미널에 남아 있는 메일 설정을 지우지는 않는다.

실행 정책으로 차단되면 보안을 낮추지 말고 기존 수동 실행 방법을 사용하거나 담당자에게 문의한다. 이 실행 파일은 로컬 실행 편의용이며 기존 로그인 JWT, 재설정 API, DB 비밀번호 저장 방식을 바꾸지 않는다. JDK 17과 접속 가능한 Oracle DB가 필요하다.

## 수동 설정 방법

1. Oracle의 프로젝트 계정에서 `05_password_reset.sql`을 한 번 실행한다. 기존 USERS 테이블을 삭제하거나 다시 만들 필요는 없다.
2. 보내는 메일 계정이 준비되면 아래 환경변수를 백엔드 터미널에 설정한다. 비밀번호는 파일이나 GitHub에 넣지 않는다.

```powershell
$env:MAIL_HOST = "메일 업체의 SMTP 주소"
$env:MAIL_PORT = "587"
$env:MAIL_USERNAME = "보내는 계정"
$env:MAIL_PASSWORD = "메일 업체에서 발급한 앱 비밀번호"
$env:MAIL_FROM = "보내는 이메일 주소"
$env:FRONTEND_URL = "http://localhost:5173"
.\gradlew.bat bootRun
```

위 설정은 STARTTLS를 사용하는 587번 포트 기준이다. 실제 값과 앱 비밀번호 발급 방법은 사용할 메일 업체에서 확인한다. 기존 Oracle, JWT 환경변수도 필요하다. 메일 설정이 없으면 발송 API는 503으로 응답한다.

## 처리 순서

- `POST /api/users/forgot-password`: 이메일 입력 → 무작위 링크 생성 → 해시와 만료 시간을 DB에 저장 → 메일 전송
- `POST /api/users/reset-password`: 링크 토큰과 새 비밀번호 입력 → 사용 가능 여부 확인 → BCrypt 해시로 저장 → 링크 사용 처리
- 링크는 15분 동안 한 번 사용한다. 회원별 재발송 간격은 1분이다. 다시 발송하면 이전 링크는 사용할 수 없다.
- 가입 여부가 드러나지 않도록 정상 응답은 같은 안내 문구를 사용한다. 전송 실패는 성공으로 표시하지 않는다.
- 토큰은 링크의 # 뒤에 넣어 프론트 서버의 요청 주소에 남지 않게 한다. 토큰이나 메일 본문을 로그에 출력하지 않는다.
- 로그인은 기존 JWT 방식 그대로다. 비밀번호 재설정으로 이미 발급된 다른 기기의 JWT까지 취소하지는 않는다.

## 확인 순서

메일 설정 후 테스트용 회원으로 요청한다. 메일 링크에서 새 비밀번호를 저장하고 로그인한다. 기존 비밀번호로 로그인되지 않는지, 같은 링크를 다시 사용할 수 없는지, 15분 지난 링크가 거절되는지 확인한다. DB의 USERS 비밀번호는 평문이 아닌 BCrypt 해시여야 한다.

실제 운영 전에는 HTTPS 주소를 FRONTEND_URL에 지정하고, 프록시 또는 서버에서 IP 기준 요청 횟수 제한도 설정한다. 현재 구현의 1분 제한은 회원별 메일 재발송에만 적용된다.

## 메일 계정 없이 검사하기

`PasswordResetFlowTest`는 테스트 실행 중에만 임시 H2 DB와 로컬 SMTP 수신기를 만든다. 실제 Oracle 계정이나 외부 메일 계정이 필요하지 않다. 테스트용 회원의 가입, 메일 링크 수신, 비밀번호 변경, 새 비밀번호 로그인, 기존 비밀번호 거절, 링크 재사용·만료·재발급을 검사한다. 테스트가 끝나면 메일 수신기는 종료된다.

```powershell
.\gradlew.bat test --tests com.comcheck.comcheck.domain.user.service.PasswordResetFlowTest
```

이는 서버 기능 검사다. 실제 메일 업체의 SMTP 인증이나 Oracle에 추가한 테이블까지 확인한 것은 아니므로, 계정 설정 후 실제 환경에서도 위 확인 순서를 진행한다.
